# Засоби операційних систем для аналізу і перевірки стану мережі

Лабораторна робота з курсу комп'ютерних мереж. Проєкт присвячений дослідженню принципів функціонування та практичного застосування основних діагностичних утиліт стеку TCP/IP, вбудованих в операційну систему Windows.

## Мета роботи

Дослідження принципів роботи основних мережевих утиліт, призначених для перевірки конфігурації та тестування мережевих з'єднань в мережах на основі ТСР/ІР: ARP, IPCONFIG, NETSTAT, ROUTE, PING, TRACERT, HOSTNAME, Whois та ін.; придбання елементарних навичок мережевого адміністрування.

## Досліджуване середовище

Параметри робочої станції та локальної мережі під час дослідження:

- **Ім'я хоста:** `WIN-LVTB26HIJCE`;
- **Мережевий адаптер:** `Intel(R) Wi-Fi 6 AX201 160MHz`;
- **Фізична адреса (MAC):** `A0-29-42-8C-2A-03`;
- **Локальна IP-адреса:** `192.168.1.9` (маска `255.255.255.0`);
- **Шлюз за замовчуванням (Default Gateway):** `192.168.1.1`;
- **DNS-сервери:** `192.168.11.1`, `8.8.8.8`, `192.168.1.1`.

## Досліджені утиліти та їх призначення

- **`hostname`** — визначення імені локального вузла;
- **`ipconfig`** — виведення повної поточної конфігурації мережевих інтерфейсів, шлюзів та адрес DNS/DHCP;
- **`ping`** — діагностика цілісності стека протоколів (loopback `127.0.0.1`), перевірка досяжності віддалених серверів, визначення MTU та оцінка джитеру;
- **`arp`** — перегляд таблиці динамічної та статичної відповідності між IP-адресами (L3) і MAC-адресами (L2);
- **`route`** — аналіз таблиці маршрутизації хоста, додавання та видалення статичних маршрутів;
- **`netstat`** — моніторинг активних мережевих підключень, аналіз станів TCP-сесій (`ESTABLISHED`, `CLOSE_WAIT`, `TIME_WAIT`) та зіставлення сокетів із PID процесів ОС;
- **`tracert`** — визначення маршруту й проміжних хопів до вітчизняних та закордонних хостів;
- **`whois`** — отримання інформації з баз даних регіональних інтернет-реєстраторів (RIPE NCC, APNIC) про приналежність IP-діапазонів та автономних систем.

## Вимоги

Для повторення та перевірки результатів необхідні:

- операційна система Windows (або еквівалентні інструменти в Linux/macOS);
- командний рядок (`cmd`) або `PowerShell` з правами адміністратора (для керування таблицею `route`);
- доступ до мережі Інтернет;
- вебпереглядач для Whois-запитів.

## Основні результати та спостереження

1. **Тестування MTU через ICMP Ping:**
    - При розмірі корисного навантаження `1472` байти із забороною фрагментації (`ping -l 1472 -f`) пакет проходить без втрат (разом із 20 байт IP + 8 байт ICMP формує рівно 1500 байтів).
    - При спробі відправити `1473` байти зафіксовано помилку перевищення ліміту MTU (`Packet needs to be fragmented but DF set`) та 100% втрат, що підтвердило стандартний розмір MTU каналу у 1500 байтів.

2. **Ручне трасування зміною TTL:**
    - Почергове надсилання луна-запитів із ключем `-i` (`ping -i 1`, `ping -i 2`, `ping -i 3`) дозволило покроково ідентифікувати перші три транзитні вузли на основі відповідей `TTL expired in transit`: `192.168.1.1` → `192.168.11.1` → `10.0.0.1`.

3. **Географічна затримка та трасування до серверів ВНЗ:**
    - **КПІ ім. Ігоря Сікорського (`kpi.ua`, Україна):** 9 хопів, середній RTT ~20 мс;
    - **ETH Zurich (`ethz.ch`, Швейцарія):** 11 хопів, середній RTT ~51 мс (вихід на європейську точку обміну Netix);
    - **Сеульський національний університет (`snu.ac.kr`, Південна Корея):** магістральний стрибок через мережу KREONET із затримкою понад 280 мс; кінцеві вузли закриті корпоративним брандмауером, що блокує службовий ICMP-трафік (тайм-аути хопів 14–30).

## Особливості реалізації

- Експериментально підтверджено повну функціональну готовність локального мережевого стеку операційної системи шляхом тестування замкненої петлі зворотного зв'язку (`127.0.0.1`).
- Відпрацьовано маніпуляції з таблицею маршрутизації: ручне додавання статичного маршруту до мережі `163.32.0.0/16` через шлюз `192.168.1.1` командою `route add` та його подальше коректне видалення через `route delete`.
- За допомогою комбінації утиліти `netstat -no` та Диспетчера завдань Windows виконано прив'язку мережевих сокетів до конкретних PID додатків (зокрема процесів браузера `chrome.exe`).
