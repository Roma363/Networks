# Налаштування прикладних протоколів стеку TCP/IP

Лабораторна робота з курсу комп'ютерних мереж. Проєкт присвячений вивченню архітектури та налаштуванню локальної мережі із серверами прикладного рівня (**DHCP**, **DNS**, **FTP**, **HTTP**) у середовищі моделювання **Cisco Packet Tracer**.

## Мета роботи

Вивчення архітектури та налаштування локальної обчислювальної мережі, до складу якої входять три сервери: DNS, DHCP і FTP (HTTP), із використанням комутувального мережевого пристрою (комутатора).

## План розподілу адрес

Для адресації вузлів локальної мережі використано підмережу `132.161.0.0/24`:

- **DHCP-сервер:** `132.161.0.1` (маска `255.255.255.0`) — перша статична мережева конфігурація;
- **DNS-сервер:** `132.161.0.2` (маска `255.255.255.0`) — служба розв'язання доменних імен;
- **FTP / HTTP-сервер:** `132.161.0.3` (маска `255.255.255.0`) — файлове сховище та вебсервер;
- **Мережевий принтер (`Printer0`):** `132.161.0.4` (маска `255.255.255.0`);
- **Маршрутизатор (`Router0`):** `132.161.0.254` (шлюз за замовчуванням);
- **Динамічний пул DHCP (`serverPool`):** починається з адреси `132.161.0.15`, максимум 40 клієнтів.

## Використані служби та протоколи

- **DHCP:** автоматична видача мережевих параметрів (IP-адреси, маски, шлюзу за замовчуванням `132.161.0.254` і DNS-сервера `132.161.0.2`);
- **DNS:** зіставлення доменних імен та IP-адрес:
  - `A Record`: `ftp.kn.kpi.ua` → `132.161.0.3`;
  - `A Record`: `ns.kn.kpi.ua` → `132.161.0.2`;
  - `CNAME`: `www.kn.kpi.ua` → `ns.kn.kpi.ua`;
- **FTP:** організація віддаленого файлового сховища з авторизацією користувачів;
- **HTTP:** розміщення вебсторінки `index.html` і доступ до неї через браузер;
- **ICMP:** діагностика мережевої доступності вузлів.

## Вимоги

Для запуску та перевірки проєкту потрібні:

- емулятор мереж Cisco Packet Tracer версії 8.0 або новішої;

## Запуск і перевірка

Відкрийте файл `topology.pkt` у Cisco Packet Tracer.

### Перевірка отримання налаштувань через DHCP

На клієнтах `Laptop0` і `PC0` відкрийте командний рядок та виконайте:

```bash
ipconfig /release
ipconfig /renew
```

Очікуваний результат: клієнти отримують адреси з діапазону `132.161.0.16–132.161.0.17`.

### Перевірка розв'язання доменних імен через DNS

```bash
nslookup ftp.kn.kpi.ua
nslookup www.kn.kpi.ua
```

Очікувана відповідь: успішне зіставлення імені `ftp.kn.kpi.ua` з IP-адресою `132.161.0.3`.

### Тестування FTP-сервера

На робочій станції `Laptop0` створіть файл `Benza.txt`.

Підключіться до сервера та передайте файл:

```bash
ftp ftp.kn.kpi.ua
put Benza.txt
dir
```

Для завантаження файлу на робочу станцію `PC0` виконайте:

```bash
ftp ftp.kn.kpi.ua
get Benza.txt
```

### Перевірка HTTP-сервера

На клієнті відкрийте **Desktop → Web Browser** і введіть:

```text
http://ftp.kn.kpi.ua
```

Вебсторінка має відобразити заголовок **«Hello World»**.

### Перевірка наскрізної доступності через ICMP Ping

```bash
ping 132.161.0.1
ping 132.161.0.2
ping 132.161.0.3
ping 132.161.0.4
```

Очікуваний результат: `0% loss` за мінімальних затримок.

## Особливості реалізації

- Сервіси FTP і HTTP об'єднано на одному фізичному сервері `Server-PT FTP`.
- Перші 14 адрес хостів статично зарезервовано для інфраструктурного обладнання (серверів і мережевого принтера).
- Реалізовано взаємодію прикладних протоколів: доступ до веб- і FTP-ресурсів здійснюється за доменними іменами завдяки взаємодії зі службою DNS.
